desc: Symptoms, likely causes, and the exact command to run. ---

Start with node dist/cli.js doctor (or pigeon doctor). It checks pairing, Keychain, the service, the Codex runtime, the skill, MCP tools, and the Slack credential.

Setup and Slack

Pigeon does not respond in Slack
  1. Run doctor. Is the background service running and the Slack credential valid?
  2. Did you pair? status says “not paired” until you DM the pair … line from your account.
  3. Are you in the Messages tab of the Pigeon app? Pigeon ignores channels and edited messages.
  4. Are you messaging from the same workspace and Slack user you paired?
{{sh:terminal}} $ node dist/cli.js status $ node dist/cli.js logs {{/sh}}
App token problems (“could not validate or securely store these tokens”)

The app token must start with xapp- and carry only connections:write. The bot token must start with xoxb- and come from an installed app. Setup validates the bot token with auth.test and the app token with apps.connections.open; the terminal prints which stage failed (bot-validation, app-validation, keychain-bot, keychain-app).

  • bot-validation: reinstall the app and copy the token again.
  • app-validation: regenerate the app-level token with connections:write; check Socket Mode is enabled.
  • keychain-*: see the Keychain item below.
Missing OAuth permissions

Under OAuth & Permissions → Bot Token Scopes you need chat:write and im:history. Under Event Subscriptions the bot event message.im. If you edited the app, the simplest repair is to compare against slack-manifest.json (App Manifest page), then reinstall the app and run setup again.

Socket Mode disconnects, or “Slack disconnected”

Ordinary connection loss reconnects automatically. If it persists: check the network, that the app was not revoked or uninstalled, and that the app token was not regenerated or deleted. doctor prints “Slack Socket Mode credential: valid” or “revoked, expired, or unreachable”. Fix the second by rerunning setup.

Keychain credential unavailable

Unlock the login Keychain and allow the intended executable. Pigeon stores items dev.pigeon.slack.bot and dev.pigeon.slack.app with account pigeon. There is no plaintext fallback. Never paste tokens into logs or issues.

Background service stopped or stale
{{sh:terminal}} $ node dist/cli.js install-service $ launchctl print gui/$(id -u)/dev.pigeon.companion {{/sh}}

The service uses the Node installation that existed when it was installed. If you removed or upgraded that Node, reinstall the service.

Codex and sessions

Codex session not found / “I can’t see a live Codex session”
  • Open Codex normally and start a task. Check codex app-server daemon version.
  • The window may use a private or embedded server, another CODEX_HOME, a custom executor, or --no-daemon. History alone does not make a session controllable.
  • “Daemon package missing”: install a supported official Codex distribution. Pigeon does not repair managed packages.
{{sh:terminal}} $ node dist/cli.js sessions {{/sh}}
“That session has gone offline”

The bound session is no longer loaded. Pigeon sent nothing. Reopen it in Codex, then DM sessions and Connect again. See Sessions and recovery.

Main session cannot be controlled

Controls apply only to a thread loaded in the shared daemon. A second app-server cannot take over a thread: Codex rejects it with an active-writer error, and Pigeon never bypasses that lock. Use the session from the client that owns it, or reopen it through the shared daemon.

Ownership conflict or “Pigeon is already running”

An atomic lock prevents two Pigeon consumers. Stop the service before pairing manually, and do not run daemon while the LaunchAgent is active.

“Conversational fork unavailable”

There is no fork feature in this release, so there is nothing to enable. Free-form questions go to the original session. See routing.

Skill not discovered, or MCP registration failed

doctor prints skillDiscovered and mcpToolsVerified. Run install-agent to repair. Setup refuses to overwrite a pigeon skill or MCP server it does not own, or an edited pigeon:begin block in AGENTS.md. Review and remove it manually, then rerun. Skills load in new sessions, so restart an old one.

{{sh:terminal}} $ node dist/cli.js install-agent $ codex mcp get pigeon --json {{/sh}}

Approvals and delivery

Pending approval expired or unavailable

Controls last 10 minutes and are invalidated by a Pigeon reconnect, a local approval, or a Codex restart. Unsupported requests (file changes, extra permissions, truncated commands) are never offered. Review it in Codex.

“I couldn’t confirm delivery”

Pigeon will not replay a possibly-delivered instruction. Look at the session in Codex, then resend if needed. Queued messages expire after five minutes; offline stop requests are never queued.

Duplicate or old replies after reconnect

Notifications are at-least-once. A crash after Slack accepted a post can duplicate it. It cannot cause duplicate Codex execution.
