Pigeon connects the Codex sessions already running on your Mac to a private Slack conversation. Ask what the agent is doing, steer it, approve a command, or answer its question without going back to your desk.

Preview, macOS only. Tested against Codex CLI 0.169.0 and its shared daemon 0.169.1. The package is not yet published to npm, so installation is from a source checkout. See what is verified, experimental, and unsupported.

How the pieces fit

Pigeon is a small local service. It speaks Slack over an outbound Socket Mode connection and talks to Codex through the shared local daemon that Codex itself already runs. There is no cloud component and no second model.

You → Slack DM → Pigeon (on your Mac) → existing Codex daemon → your original session
                                   ← observed activity, requests, results ←

Two things are worth knowing up front, because the rest of the docs build on them:

  • Messages are routed by simple, deterministic rules. A fixed set of phrases is answered locally from observed state. Everything else goes to Codex as an instruction. Read the exact rules.
  • Pigeon talks to live sessions only. A saved conversation is not a live connection. Sessions and recovery explains what that means.

About the screenshots

Slack's developer pages need a signed-in browser. These docs label every visual honestly: Real rendering means it was rendered from Pigeon's actual markup or output, and Illustrative diagram means it is a drawing of a Slack page with numbered callouts, not a captured screenshot. Slack's labels change over time; if a button is worded differently, follow the highlighted position and the text in the step.
