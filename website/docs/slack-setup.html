    Set up

    Slack setup

    Slack makes you do this once. The manifest sets every scope, event, and Socket Mode switch for you, so the manual part is: create, install, copy two tokens.

    Why not one click? Slack requires the app to be installed and a Socket Mode token to be generated by a person in the browser. Pigeon does not fake an OAuth flow, and it does not ask for your Slack password or an app-configuration token.

    Before you begin#

    • You ran node dist/cli.js setup, so the local page is open. Keep it open; you will paste into it at the end.
    • You are signed in to Slack in your browser, in the workspace where you want to chat with Pigeon.
    • Slack Free allows ten installed apps; Pigeon uses one.

    1. Open the Slack developer apps page#

      Go to api.slack.com/apps and choose Create New App.

    2. Choose the manifest option#

      Slack words this as From a manifest; Pigeon's setup page calls it “Paste a manifest”. Either way, it is what removes most of the manual configuration.

    3. Pick the workspace and paste the manifest#

      Select your workspace, then paste the JSON from the local setup page (or from slack-manifest.json in the repository). Choose JSON if Slack offers a format switch. Review the summary and create the app.

      slack-manifest.json
      {
  "display_information": {
    "name": "Pigeon",
    "description": "Your coding agent is one message away.",
    "background_color": "#26443b"
  },
  "features": {
    "bot_user": { "display_name": "Pigeon", "always_online": false },
    "app_home": {
      "home_tab_enabled": false,
      "messages_tab_enabled": true,
      "messages_tab_read_only_enabled": false
    }
  },
  "oauth_config": { "scopes": { "bot": ["chat:write", "im:history"] } },
  "settings": {
    "socket_mode_enabled": true,
    "interactivity": { "is_enabled": true },
    "event_subscriptions": { "bot_events": ["message.im"] },
    "org_deploy_enabled": false
  }
}

      Because the manifest enables Socket Mode, Interactivity and the message.im event, you do not toggle those by hand, and no Request URL is needed.

    4. Install to your workspace#

      On Basic Information, choose Install to Workspace and approve. Slack lists only the two scopes below.

    5. Copy the Bot User OAuth Token#

      Open OAuth & Permissions. Copy the token that starts with xoxb-. Paste it into the Bot token field of the local setup page. Confirm the bot scopes are exactly chat:write and im:history.

    6. Generate the app-level token#

      Back on Basic Information, scroll to App-Level Tokens and choose Generate Token and Scopes. Name it Pigeon, add only connections:write, and generate.

      Copy the token that starts with xapp- into the App-level token field.

    7. Save to Keychain#

      Press Save to Keychain on the local page. Pigeon checks both tokens against Slack before storing anything. If it says it could not validate them, see app token problems.

    8. Pair your Slack user#

      The terminal now prints In a direct message to Pigeon, send: pair …. Open the Pigeon app under Apps in Slack, open the Messages tab, and send exactly that line. Pigeon replies that you are connected.

      Pairing is what makes Pigeon answer only you. Do it from the Slack account you will actually use.

    9. Verify#

      terminal
      $ node dist/cli.js status
$ node dist/cli.js doctor

      Then DM sessions to Pigeon. If you see a list (or “I can’t see a live Codex session yet”), Slack is working end to end.

    What each permission is for#

    PermissionUsed for
    chat:write (bot)Posting the agent's messages and the approval buttons.
    im:history (bot)Receiving message.im events from your DM with the bot.
    connections:write (app-level)Opening the Socket Mode WebSocket.

    Not requested: channel history, search, user directory, file upload, admin scopes, a signing secret, a public webhook, or a user OAuth token. The bridge also drops any event that is not a direct message from your paired user and workspace.

    Refreshing credentials#

    Rerun setup. It stops the service during the flow and keeps your pairing if the workspace is unchanged. Leave the app-token field blank to keep the saved one. A different workspace needs pairing again.

    Slack interface reference: the diagrams above were drawn from Slack's documented setup flow for apps created from a manifest. They have not been captured from a live signed-in session, so wording may differ slightly.
