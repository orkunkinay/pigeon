    Security

    A paired Slack identity can instruct Codex with the permissions Codex already has. Treat that Slack account, its logged-in devices, the bot token, and your macOS account as trusted control surfaces. This preview has not had an independent security audit.

    What Pigeon accesses#

    • Codex's local control socket, to list threads, read recent turns, steer, interrupt, and answer native requests.
    • Your direct messages with the Pigeon bot only.
    • Its own SQLite database and logs in ~/.pigeon.

    What is sent to Slack#

    Raw agent messages, command text for approvals, status excerpts, and questions. These can contain source code or other private content. Only bind projects whose output you are willing to send to Slack. Pigeon does not detect or redact secrets in model output. Slack keeps its own copies.

    How tokens are stored#

    As macOS Keychain generic-password items dev.pigeon.slack.bot and dev.pigeon.slack.app. Values are passed to Keychain on stdin, not in process arguments. There is no plaintext fallback. The setup page binds to 127.0.0.1 on a random port and path, checks Host and Origin, requires a CSRF value, forbids framing, and expires after 20 minutes.

    How authorization works#

    Pairing needs a random phrase shown only in your terminal. After that, only direct messages from that user in that workspace are accepted. Wrong users, other channels, edits and bot events are rejected before anything is stored.

    How approvals are handled#

    Each control is one-use and bound to the connection generation, the exact native request ID, the thread, the Slack conversation and a 10-minute expiry. Typing “yes” is never an approval. A local decision, reconnect or expiry invalidates the control. Pigeon never approves automatically. File changes, permission bundles, truncated commands and unknown requests cannot be approved remotely.

    Local retention#

    The database is mode 0600 inside a 0700 directory. Completed message bodies are cleared. One bounded last question and reply per Slack thread is kept for follow-ups until the binding changes or you uninstall. This is bounded retention, not forensic erasure.

    What Pigeon does not do#

    • No TCP control port, tunnel, or hosted component.
    • No scraping of memory or terminals, key injection, rollout edits, or lock bypass.
    • No access to Microsoft Authenticator or any identity provider. The agent must verify real sign-in state.
    • No collection of your Slack password, a user OAuth token, signing secret, or app-configuration token.
    • No collection of passwords, OTPs, recovery codes or tokens through the MCP tools.

    Revoking access#

    pigeon uninstall removes the service, local state and Keychain items. Remove the Slack app in Slack to revoke the tokens at the source. Report vulnerabilities privately; no reporting endpoint is configured until the repository is published, so do not post secrets or exploit details publicly.
