    Architecture

    Pigeon is a companion to a runtime that already owns the agent. Slack input crosses a transport boundary into the same Codex thread the normal UI uses.

    PathResponsibility
    src/transports/slack/Bolt Socket Mode bridge and authenticated ingress (pairing, DM-only, workspace/user check).

    src/security/keychain.tsmacOS Keychain access.

    Runtime contract#

    • Joining uses thread/resume on the same server after a loaded check. The protocol has no atomic “subscribe only if loaded”. docs/UPSTREAM.md proposes one.
    • Status reads metadata and the latest turn only. Steering requires expectedTurnId; a turn change makes it fail and it is never retried as turn/start.
    • Inbound messages are stored before Slack's envelope is acknowledged; events are deduplicated by ID. Instructions move queued → sending → done; a crash in sending becomes uncertain.
    • Outbound posts are chunked, paced at one per second, retried with backoff. Delivery is at-least-once.

    Not in the code#

    There is no conversation fork, no main-agent controller distinct from the adapter, and no session recovery manager. The longer repo doc is docs/ARCHITECTURE.md.
