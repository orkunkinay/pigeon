The problem

Agents can work for hours. Then they need you.

A sign-in to approve. A decision only you can make. A command waiting for permission. If you are not at your computer, the agent just stops.

What Pigeon does

    How it works

    Ask the status. Direct the session. Approve with a button.

    Pigeon does not hand every Slack message to the agent as if it were the same kind of thing. Small, predictable rules decide where each message goes. No model guesses your intent.

    “What are you doing?”a recognised status phrase
    →
    Answered from observed stateReads what Codex already did. Creates no turn, interrupts nothing.
    “Focus on latency first.”any other message
    →
    Sent to your original sessionSteers the active turn, or starts the next one if idle.
    Codex asks to run a commandrequest from Codex
    →
    Approve once / DenyA one-use button bound to that request. Typing “yes” never approves.

    Honest gap. Pigeon does not yet fork a session to discuss work without touching it, and it cannot resume a stopped conversation. A free-form question goes to the working session like any instruction. Not built See the exact routing rules.

    Same session, not a chatbot

    Pigeon joins the Codex session that is already running, through the shared local daemon Codex itself provides. It does not start a replacement model or read your terminal. In a live test the original worker recalled a marker from its first task, one injected mid-turn, and one sent from Slack. How it finds your sessions.

    The design

    Route by intent, never send every message to main.

    This sketch is the architecture Pigeon is built around: casual questions go to a read-only fork, instructions to the main session, approvals through a coordinator, and stopped work through a recovery manager. It is the target design, not a description of today's code. Click the image to enlarge it.

    Built
    • Intent routing (a fixed phrase list)
    • Approval handling with one-use buttons
    • Skill and four MCP tools
    • Live session registry and thread-to-session mapping
    • Status answered from observed state
    Partly
    • Main control: steering and interrupts exist, in the Codex adapter rather than a separate controller
    • Authentication help: via the agent's pigeon_request_human_action tool
    Not built
    • Conversational fork (read-only forked session)
    • Session recovery manager
    • Intent classification beyond fixed phrases

    Quick start

    Install from source, connect Slack once.

    macOS, Node.js 24+, Codex signed in, and permission to install a custom Slack app.

    $ git clone https://github.com/Murat-Barkin-Kinay/pigeon.git
$ cd pigeon
$ npm ci
$ npm run build
$ node dist/cli.js setup

    Clone URL applies once the repository is public. In an existing checkout, start at npm ci.

    1. Create the Slack app from a manifest. It sets every scope and event for you.
    2. Copy two tokens into the local page. They go to macOS Keychain.
    3. Pair by DMing the one-time phrase to Pigeon.
    4. Open Codex, DM sessions, press Connect, and say hello.

    Follow the Slack setup guide

    The npm name pigeon is a different project. Do not use npx pigeon.

    Read the architecture notes

    Open source, local first

    No cloud. No tunnel. No second model.

    Runs on your Mac

    A LaunchAgent, SQLite, and Slack Socket Mode. Nothing to host, no public URL, no signing secret.

    Locked to you

    Pairing with a phrase only your terminal shows. Only your DMs are accepted. Tokens live in Keychain.

    Approvals stay honest

    One-use buttons, ten-minute expiry, never automatic. Codex's own policy still applies. Security model.

    What is real, and what is not

    Verified
    • Attach to a live session
    • Slack round trip
    • Steer and interrupt
    • Command approval
    • Agent-initiated messages
    Experimental
    • Codex daemon restarts
    • Sleep and network loss
    • Codex desktop app
    • Other Codex versions
    Not built
    • Conversational fork
    • Resuming stopped sessions
    • Windows and Linux
    • File-change approvals from Slack
